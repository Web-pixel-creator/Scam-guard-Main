Production smoke scripts:

- `prod-smoke.ts`: public app, `/healthz`, delivery-mode-aware webhook auth,
  Telegram pending state, polling leader and AI provider.
- `prod-telegram-inline-smoke.ts`: synthetic Inline transport/non-persistence
  boundary. In polling mode it proves webhook shutdown and zero side effects,
  but deliberately does not claim real Inline handler or client delivery.
- `prod-monitor.ts`: recurring delivery-mode-aware app/Telegram/AI monitor with authenticated polling-leader health.
- `switch-telegram-to-polling.ts`: verifies an active polling leader before removing the webhook without dropping pending updates.
- `polling-resource-soak.ts`: controlled in-memory polling failure model and
  resource profile; emits progress/final JSON and makes no Telegram, database,
  reputation or AI-provider call.
- `qr-worker-resource-soak.ts`: parameterized isolated QR decoder corpus,
  queue/resource and worker termination/recovery profile; the Docker image
  bundles it at `dist/ops/qr-worker-resource-soak.mjs`.
- `prod-family-shield-smoke.ts`: synthetic Family Shield invite/accept/notify/revoke/cleanup.
- `prod-security-smoke.ts`: RLS/security checks for sensitive tables, reputation appeals, shared rate-limit buckets, embed origin events and maintenance/stat/rate-limit RPC access.
